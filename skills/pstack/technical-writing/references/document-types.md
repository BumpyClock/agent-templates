# Document types

Use the Diátaxis distinction when document purpose or organization needs a decision.
Do not force a short document into separate files to satisfy a category.
Preserve a supplied template unless the user requests structural changes.

## Tutorial

Guide a learner through a concrete result.
Include prerequisites, useful checkpoints, and expected output.
Keep background detail close to the step that needs it, or link to an explanation.

## How-to guide

Help a reader complete a specific task.
State necessary conditions before actions.
Include alternatives only when the reader must choose between valid paths.

## Reference

Describe the interface or system for lookup.
Match its organization and terminology.
Include relevant options, defaults, limits, errors, and examples.
State uncertainty when a fact is not established.

## Explanation

Explain a bounded question about behavior or design.
Include the context, rationale, alternatives, and tradeoffs that answer that question.
Distinguish documented intent from an inference about the source.

## Mixed documents

Use separate sections or links when readers have different tasks.
Keep a table, example, or brief explanation inline when it helps the current task.
For PR descriptions and commit messages, follow repository conventions rather than this document taxonomy.
